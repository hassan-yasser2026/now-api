# NOW Customer Web

واجهة عميل مستقلة مبنية بـ Next.js. التطبيق لا ينشئ API أو قاعدة بيانات
جديدة؛ الصفحات العامة تقرأ المتاجر والمنتجات من API الحالي نفسه.

## التشغيل محليًا

```powershell
cd web
Copy-Item .env.example .env.local
npm run dev
```

عدّل `NOW_API_URL` في `.env.local` إلى عنوان الـ API الحالي عند استخدام بيئة
محلية. القيمة الافتراضية تشير إلى API الإنتاج. لا تضع أسرارًا في متغيرات
`NEXT_PUBLIC_*`.

## البناء والفحص

```powershell
npm run lint
npm run build
```

## ما تم تنفيذه

- الصفحة الرئيسية تعرض المتاجر المفتوحة بتحميل server-side.
- الصفحة الرئيسية تدعم البحث المحلي عن المتاجر والمنتجات المضمّنة في رد API،
  وتعرض الأعلى تقييمًا كاختيارات استنادًا إلى تقييمات العملاء، ويمكن ترتيب
  المتاجر الأقرب بعد إذن الموقع مع حساب المسافة المباشرة من إحداثيات المتاجر.
- صفحات المتجر والمنتج تُحمّل من المسارات `/api/stores` و
  `/api/stores/:storeId/menu` الحالية، مع metadata عربية ومدة إعادة تحقق
  3600 ثانية (ساعة) لتقليل الطلبات المتكررة إلى API.
- تسجيل دخول وتسجيل عميل عبر API الحالي، مع تخزين JWT في HTTP-only cookie
  وعدم إرساله إلى JavaScript في المتصفح.
- صفحتا الحساب والطلبات تتحققان من الجلسة عبر `/api/auth/me` وتحوّلان الزائر
  إلى تسجيل الدخول. بيانات الطلبات تُحمّل من API مع التحقق من ملكية العميل.
- تفاصيل المنتج تعرض السعر والوصف والصورة والتقييمات والخصم المتاح في API،
  مع structured data للمنتج لمحركات البحث.
- سلة الويب تحفظ المنتجات والكميات محليًا في `localStorage`، وتدعم تعديل
  الكميات والإزالة والإفراغ ومزامنة التغييرات بين تبويبات المتصفح.
- Checkout محمية للعميل، تحفظ عنوان التوصيل وإحداثياته محليًا، وتطلب إذن
  الموقع من المتصفح. إنشاء الطلب يمر عبر وسيط server-side يرفق جلسة HTTP-only
  ويرسل المنتجات والعنوان والدفع النقدي إلى API الحالي.
- صفحة تفاصيل الطلب محمية وتعرض الحالة والمنتجات والعنوان والمبالغ التي يعيدها
  API، وتحدّث الحالة تلقائيًا كل 30 ثانية.
- اتجاه RTL وتصميم responsive للهاتف واللوحي وسطح المكتب.

## حدود وخطوات لاحقة

- استعادة كلمة المرور غير متاحة: لم نجد endpoint عامًّا لها في الـ API الحالي؛
  الموجود هو تغيير كلمة المرور من داخل الحساب الموثق.
- السلة المحلية لا تتزامن مع تطبيق الهاتف، وتسمح حاليًا بمنتجات متجر واحد
  في كل مرة. **TODO:** بحث واعتماد واجهة سلة مشتركة إذا أُريدت المزامنة بين
  الهاتف والويب. لا يوجد endpoint عام لحفظ دفتر العناوين؛ لذلك العنوان
  والإحداثيات محليان في متصفح الويب فقط.
- Checkout يرسل الإحداثيات التي يوافق العميل على مشاركتها، لكن تنفيذ إنشاء
  الطلب الظاهر في backend الحالي لا يربط `latitude` و`longitude` بسجل الطلب؛
  يلزم تحديث backend بموافقة منفصلة إذا كان حفظ الموقع مطلوبًا.
- لا يوفّر API الحالي تقديرًا لرسوم التوصيل قبل إنشاء الطلب، كما لا يحفظ
  ملاحظات الطلب عبر endpoint الإنشاء الظاهر؛ لا يضيف الويب رسومًا أو ملاحظات
  من عنده، ويعرض المبالغ التي يعيدها الخادم. واجهة الهاتف ترسل
- endpoint المتاجر العام لا يرفق أسماء فئات المتاجر أو المنتجات، ولا يوفّر
  endpoint عامًّا للفئات أو علامة متجر مميز. تعرض الصفحة فلاتر الفئات عندما
  تكون أسماء الفئات ضمن بيانات API، وتستخدم الأعلى تقييمًا بدل ادعاء وجود
  إعداد «مميز» إداري؛ دعم الفئات يحتاج إتاحة بياناتها في API. واجهة الهاتف ترسل
  `CASH_ON_DELIVERY`، لكن تنفيذ backend الموجود ينشئ معاملة بحالة `PENDING`
  من دون حفظ طريقة الدفع؛ لذلك لا يتيح الويب وسيلة دفع أونلاين ولا يدّعي أن
  طريقة الدفع سُجلت في المعاملة.
- إضافة اختبارات تكامل وSEO إضافي مثل sitemap ثم النشر على استضافة تدعم تشغيل
  Next.js server-side rendering.

المشروع منفصل داخل `web/` ولا يغيّر ملفات الموبايل أو الـ backend.
